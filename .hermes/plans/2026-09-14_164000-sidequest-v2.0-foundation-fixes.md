## Architecture / proposed approach
Three independent, non-overlapping fixes — each touches only the files needed and ships with a regression test.

1. **Update UX (single source of truth + once-per-session gate):** Make `UpdatedNotice` and `UpdateBanner` read from **one** shared update-orchestrator module (`src/lib/updates.ts`) that memoizes "have we shown this version's notice?" in a session flag + persistent storage. No component shows its own duplicate. App.tsx mounts a single `<UpdateNotice />` that renders *either* the "updated" toast *or* the "available" banner, never both.
2. **Map (kill the fallback):** Remove the "API key required" debug overlay path in `MapScreen.tsx`. The `TILE_PROVIDERS` already default to Carto light/dark + OSM — the watermark only renders when a tile URL returns 401; guard that with a clean fallback-to-OSM instead of a debug label. One render path.
3. **Counts (canonical query + labels):** Introduce `src/lib/quests.ts` with a single `totalQuests()`, `questsInProvince(id)`, `activeQuestCount()` that every screen imports. Replace local `.length` reads. Add star-rating labels.

All three follow TDD: failing test → implement → verify → commit. No feature work; pure bug fixes.

#### 1a. Create `src/lib/updates.ts`
```ts
// Single source of truth for "have we shown the user an update message this session?"
const SESSION_SHOWN = new Set<string>()

export function shouldShowUpdatedNotice(version: string): boolean {
  const key = `updated:${version}`
  if (SESSION_SHOWN.has(key)) return false
  SESSION_SHOWN.add(key)
  return true
}

export function shouldShowUpdateBanner(version: string): boolean {
  const key = `banner:${version}`
  if (SESSION_SHOWN.has(key)) return false
  SESSION_SHOWN.add(key)
  return true
}

// Reset hook for tests
export function _resetUpdateGates() { SESSION_SHOWN.clear() }
```

Run test → expect **pass** (green).

## Risks, tradeoffs, and open questions

**Risks**
- **Branch confusion:** the local working copy is `origin/main` (download-center, Node/PHP files), but edits must go against `origin/source` (the app). I check out `v2-foundation-fixes` from `origin/source` at task start. If the source branch is stale, `git fetch` first. Risk: accidentally committing web-build files into the app source — mitigate by running `git status` before each commit and only `git add` the specific `src/` files.
- **Test seam for `detectJustUpdated`:** it's an async Capacitor call; the once-per-session gate is the unit-testable part (`updates.ts`), not the native path. The device test (Task 1d) covers the real path.
- **Map fallback:** if *both* Carto and OSM URLs are broken in the emulator, the test still passes (it's pure-logic) but the device test fails. Have `tile.openstreetmap.org` confirmed reachable first (`curl -o /dev/null -w "%{http_code}" https://tile.openstreetmap.org/0/0/0.png` → expect 200).

**Tradeoffs**
- Keeping `UpdateBanner` and `UpdatedNotice` as separate components under a single `UpdateNotice` wrapper is slightly more code than deleting one, but preserves both behaviors for different device states (banner = remote newer; notice = just-installed). Worth it.
- `quests.ts` re-declares the `totalQuestsInProvince` arithmetic instead of importing from `game.ts` to avoid a circular dep (`game.ts` already imports from `data/quests.ts`, and `data/quests.ts` imports `hangouts`/`events` — adding `game` → `quests.ts` → `data` is fine, but importing the other way risks a cycle). Acceptable duplication; flag for a later refactor.
